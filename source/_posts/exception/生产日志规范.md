# 生产日志规范：设计、收集与分析

## 前言

日志是生产环境排查问题的重要依据，也是监控系统的重要数据来源。然而，很多团队的日志存在混乱、不规范、难以分析的问题。本文将介绍一套完整的生产日志规范，包括日志设计、输出规范、收集方案和分析方法，帮助团队建立高效的日志体系。

## 2. 日志级别规范

### 级别定义

```
┌─────────────────────────────────────────────────────────────────┐
│                      日志级别规范                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ERROR (错误)                                                   │
│  ├─ 定义：影响功能使用的错误，需要立即处理                        │
│  ├─ 场景：                                                       │
│  │   - 数据库连接失败                                            │
│  │   - 第三方服务调用异常                                        │
│  │   - 数据处理异常                                              │
│  │   - 业务异常导致流程中断                                      │
│  └─ 示例：log.error("订单创建失败", e);                          │
│                                                                 │
│  WARN (警告)                                                    │
│  ├─ 定义：潜在问题，不需要立即处理但应关注                        │
│  ├─ 场景：                                                       │
│  │   - 重试成功                                                  │
│  │   - 非预期的业务分支                                          │
│  │   - 配置缺失使用默认值                                        │
│  │   - 性能接近阈值                                              │
│  └─ 示例：log.warn("库存不足，使用备用仓库");                     │
│                                                                 │
│  INFO (信息)                                                    │
│  ├─ 定义：重要的业务节点和系统事件                                │
│  ├─ 场景：                                                       │
│  │   - 服务启动/停止                                             │
│  │   - 业务关键流程节点                                          │
│  │   - 定时任务执行                                              │
│  │   - 用户登录/登出                                             │
│  └─ 示例：log.info("订单创建成功, orderId={}", orderId);         │
│                                                                 │
│  DEBUG (调试)                                                   │
│  ├─ 定义：开发调试信息，生产环境默认关闭                           │
│  ├─ 场景：                                                       │
│  │   - 方法入参/出参                                             │
│  │   - SQL语句                                                   │
│  │   - 中间变量值                                                │
│  └─ 示例：log.debug("查询结果, count={}", count);               │
│                                                                 │
│  TRACE (追踪)                                                   │
│  ├─ 定义：最详细的追踪信息                                        │
│  └─ 示例：记录方法调用链、性能数据                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 使用示例

```java
// 好的日志实践
@Service
@Slf4j
public class OrderService {

    public void createOrder(OrderDTO orderDTO) {
        try {
            // INFO: 业务关键节点
            log.info("开始创建订单, userId={}, productId={}",
                     orderDTO.getUserId(), orderDTO.getProductId());

            // 参数校验
            if (orderDTO.getAmount() <= 0) {
                // ERROR: 业务校验失败
                log.error("订单金额不合法, userId={}, amount={}",
                          orderDTO.getUserId(), orderDTO.getAmount());
                throw new BusinessException("订单金额必须大于0");
            }

            // 扣减库存
            boolean stockReduced = stockService.decreaseStock(
                orderDTO.getProductId(), orderDTO.getCount());

            if (!stockReduced) {
                // WARN: 非预期业务分支
                log.warn("库存不足, userId={}, productId={}, requested={}",
                         orderDTO.getUserId(), orderDTO.getProductId(),
                         orderDTO.getCount());
                throw new BusinessException("库存不足");
            }

            // 创建订单
            Order order = orderMapper.create(orderDTO);

            log.info("订单创建成功, orderId={}, amount={}",
                     order.getId(), order.getAmount());

        } catch (BusinessException e) {
            // 业务异常：记录WARN
            log.warn("业务异常, userId={}, error={}",
                     orderDTO.getUserId(), e.getMessage());
            throw e;

        } catch (Exception e) {
            // 系统异常：记录ERROR，保留完整堆栈
            log.error("系统异常, userId={}, productId={}",
                      orderDTO.getUserId(), orderDTO.getProductId(), e);
            throw new SystemException("创建订单失败", e);
        }
    }
}

// 坏的日志实践
@Service
public class BadExample {

    private static final Logger log = LoggerFactory.getLogger(BadExample.class);

    public void badLogging() {
        // 错误1: 在ERROR日志中输出非关键信息
        log.error("订单失败了");  // 缺少上下文

        // 错误2: 在循环中打印日志
        for (int i = 0; i < 1000; i++) {
            log.info("处理第{}条数据", i);  // 日志过多
        }

        // 错误3: 使用字符串拼接而非占位符
        log.info("用户" + userId + "创建订单" + orderId);  // 性能差

        // 错误4: 敏感信息记录日志
        log.info("用户密码:" + password);  // 安全问题

        // 错误5: 缺少ERROR日志
        try {
            doSomething();
        } catch (Exception e) {
            // 完全不记录日志
        }
    }
}
```

### 日志脱敏

```java
// 日志脱敏工具
@Component
public class LogMaskingUtil {

    private static final Map<String, String> MASK_PATTERNS = new HashMap<>();

    static {
        MASK_PATTERNS.put("password", "******");
        MASK_PATTERNS.put("token", "***");
        MASK_PATTERNS.put("phone", "\\d{3}\\d{4}(\\d{4})");
        MASK_PATTERNS.put("idCard", "\\d{6}\\d{8}(\\d{4})");
        MASK_PATTERNS.put("bankCard", "\\d{4}\\d{11}(\\d{4})");
    }

    public static String maskSensitiveData(String content) {
        if (content == null) {
            return null;
        }

        String masked = content;
        for (Map.Entry<String, String> entry : MASK_PATTERNS.entrySet()) {
            String fieldName = entry.getKey();
            String regex = entry.getValue();

            // 替换匹配的内容
            Pattern pattern = Pattern.compile("\"" + fieldName + "\"\\s*:\\s*\"[^\"]+\"");
            masked = pattern.matcher(masked).replaceAll(
                "\"" + fieldName + "\" : \"" + getMaskValue(fieldName) + "\""
            );
        }

        return masked;
    }

    private static String getMaskValue(String fieldName) {
        switch (fieldName) {
            case "password": return "******";
            case "token": return "***";
            case "phone": return "138****5678";
            case "idCard": return "430101********1234";
            case "bankCard": return "622202********1234";
            default: return "***";
        }
    }
}

// 使用AOP统一记录日志
@Aspect
@Component
@Slf4j
public class LoggingAspect {

    @Around("@annotation(LoggedOperation)")
    public Object logOperation(ProceedingJoinPoint point) throws Throwable {
        MethodSignature signature = (MethodSignature) point.getSignature();
        LoggedOperation annotation = signature.getMethod().getAnnotation(LoggedOperation.class);

        long startTime = System.currentTimeMillis();
        String traceId = MDC.get("traceId");

        try {
            Object result = point.proceed();

            log.info("操作完成|traceId={}|operation={}|duration={}ms|result=success",
                     traceId, annotation.value(),
                     System.currentTimeMillis() - startTime);

            return result;

        } catch (Exception e) {
            log.error("操作失败|traceId={}|operation={}|duration={}ms|error={}",
                      traceId, annotation.value(),
                      System.currentTimeMillis() - startTime,
                      e.getMessage());
            throw e;
        }
    }
}
```

```java
// 使用AOP和注解实现日志规范
@Aspect
@Component
@Slf4j
public class LoggingInterceptor {

    @Around("execution(* com.example..*Controller.*(..))")
    public Object logController(ProceedingJoinPoint joinPoint) throws Throwable {
        HttpServletRequest request = getRequest();
        String traceId = generateTraceId();
        MDC.put("traceId", traceId);
        MDC.put("userId", getUserId(request));
        MDC.put("requestUri", request.getRequestURI());

        long start = System.currentTimeMillis();
        Object result = null;

        try {
            log.info("请求开始|method={}|uri={}|params={}",
                     getMethod(), request.getRequestURI(), getParams(joinPoint));

            result = joinPoint.proceed();

            log.info("请求完成|method={}|uri={}|duration={}ms",
                     getMethod(), request.getRequestURI(),
                     System.currentTimeMillis() - start);

            return result;

        } catch (Exception e) {
            log.error("请求异常|method={}|uri={}|duration={}ms|error={}",
                      getMethod(), request.getRequestURI(),
                      System.currentTimeMillis() - start,
                      e.getMessage(), e);
            throw e;
        } finally {
            MDC.clear();
        }
    }
}
```

## 常见面试题

**Q1：如何设计日志格式？**

> 参考答案：好的日志格式应该包括：1）时间戳（精确到毫秒）；2）日志级别；3）应用名称和实例；4）链路ID（traceId）；5）用户ID；6）线程名；7）日志器名；8）消息内容；9）上下文信息（MDC）。建议使用JSON格式，便于解析和搜索。避免在日志中记录敏感信息，如密码、token等。

**Q2：日志级别如何使用？**

> 参考答案：ERROR用于影响功能的错误需要立即处理；WARN用于潜在问题不需要立即处理但应关注；INFO用于重要业务节点和系统事件；DEBUG用于开发调试信息生产环境默认关闭。使用原则：1）ERROR日志要保留完整堆栈；2）WARN日志要包含上下文信息；3）INFO日志要简洁明了；4）避免在循环中打印日志；5）使用占位符而非字符串拼接。

**Q3：如何排查生产环境的复杂问题？**

> 参考答案：1）通过traceId串联完整调用链；2）按时间范围过滤日志；3）按服务名、错误级别筛选；4）分析异常堆栈定位问题代码；5）使用聚合分析错误分布和性能；6）对比正常和异常时的日志差异；7）结合监控指标和链路追踪综合分析。

**Q4：如何保证日志的可靠性？**

> 参考答案：1）使用异步日志避免阻塞主线程；2）配置日志轮转防止磁盘满；3）日志收集使用Kafka等缓冲防止丢失；4）关键日志可以考虑双写（本地+远程）；5）定期归档和清理防止存储爆满；6）重要业务操作可以单独记录审计日志。
