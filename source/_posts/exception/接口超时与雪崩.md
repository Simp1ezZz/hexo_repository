# 接口超时与雪崩：服务降级、熔断与限流

## 前言

在分布式系统中，一个服务的故障可能导致调用方长时间等待，进而引发连锁反应，最终导致整个系统崩溃。这就是所谓的"雪崩效应"。本文将深入探讨接口超时和雪崩的成因、防御策略（服务降级、熔断、限流），以及如何在Spring Cloud和Sentinel框架中实现这些机制。

## 雪崩效应原理

```
┌─────────────────────────────────────────────────────────────────┐
│                      雪崩效应演进                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  阶段1：单点故障                                                  │
│  ┌─────────┐      ┌─────────┐      ┌─────────┐                  │
│  │Service A│      │Service B│      │Service C│                  │
│  │  正常   │─────>│   正常   │─────>│   正常   │                  │
│  └─────────┘      └─────────┘      └─────────┘                  │
│                                                                 │
│  阶段2：故障传播                                                  │
│  ┌─────────┐      ┌─────────┐      ┌─────────┐                  │
│  │Service A│      │Service B│      │Service C│                  │
│  │ 正常   │─────>│  超时   │─────>│  正常   │                  │
│  │  等待   │      │  阻塞   │      │         │                  │
│  └─────────┘      └─────────┘      └─────────┘                  │
│                        │                                        │
│                        │ 线程堆积                                │
│                        ▼                                        │
│                    ┌─────────┐                                  │
│                    │ 资源耗尽 │                                  │
│                    └─────────┘                                  │
│                                                                 │

│  ┌─────────┐      ┌─────────┐      ┌─────────┐                  │
│  │Service A│      │Service B│      │Service C│                  │
│  │  崩溃   │─────>│  崩溃   │─────>│  崩溃   │                  │
```

### 重试机制

```java
// 1. Spring Retry
@Configuration
@EnableRetry
public class RetryConfig {

    @Bean
    public RetryTemplate retryTemplate() {
        RetryTemplate retryTemplate = new RetryTemplate();

        // 指数退避
        ExponentialBackOffPolicy backOffPolicy = new ExponentialBackOffPolicy();
        backOffPolicy.setInitialInterval(1000);
        backOffPolicy.setMultiplier(2.0);
        backOffPolicy.setMaxInterval(10000);
        retryTemplate.setBackOffPolicy(backOffPolicy);

        // 重试策略
        SimpleRetryPolicy retryPolicy = new SimpleRetryPolicy();
        retryPolicy.setMaxAttempts(3);
        retryPolicy.setRetryableExceptions(Arrays.asList(
            IOException.class,
            ServiceUnavailableException.class
        ));
        retryTemplate.setRetryPolicy(retryPolicy);

        return retryTemplate;
    }
}

// 使用示例
@Service
public class ExternalService {

    @Autowired
    private RetryTemplate retryTemplate;

    public String callApi() {
        return retryTemplate.execute(context -> {
            // 业务逻辑
            return restTemplate.getForObject("http://external-api/data", String.class);
        });
    }
}

// 2. Feign重试
@Configuration
public class FeignRetryConfig {

    @Bean
    public Retryer feignRetryer() {
        // 重试次数、间隔

    }
```

### Spring Cloud降级

```java
// Feign客户端指定降级类
@FeignClient(name = "user-service",
             fallback = UserServiceFallback.class)
public interface UserClient {

    @GetMapping("/user/{id}")
    User getUser(@PathVariable("id") Long id);
}

// 降级实现类
@Component
public class UserServiceFallback implements UserClient {

    private static final Logger logger = LoggerFactory.getLogger(UserServiceFallback.class);

    @Override
    public User getUser(Long id) {
        logger.warn("User服务调用失败，降级返回默认用户");
        // 返回默认值
        User defaultUser = new User();
        defaultUser.setId(id);
        defaultUser.setName("默认用户");
        defaultUser.setDefault(true);
        return defaultUser;
    }
}

// 配置开启Hystrix
application.yml:
feign:
  hystrix:
    enabled: true
```

### Sentinel降级

```java
// 1. 引入依赖
<dependency>
    <groupId>com.alibaba.csp</groupId>
    <artifactId>sentinel-core</artifactId>
    <version>1.8.6</version>
</dependency>

// 2. 定义资源
@Service
public class ProductService {

    @Autowired
    private ProductClient productClient;

    // 使用注解定义资源
    @SentinelResource(value = "getProduct",
                     blockHandler = "getProductBlockHandler",
                     fallback = "getProductFallback")
    public Product getProduct(Long productId) {
        return productClient.getProduct(productId);
    }

    // 降级方法
    public Product getProductFallback(Long productId, Throwable t) {
        logger.error("获取商品失败，降级处理", t);
        Product defaultProduct = new Product();
        defaultProduct.setId(productId);
        defaultProduct.setName("默认商品");
        defaultProduct.setPrice(BigDecimal.ZERO);
        return defaultProduct;
    }

    // 限流处理方法
    public Product getProductBlockHandler(Long productId, BlockException e) {
        logger.warn("获取商品被限流", e);
        throw new BusinessException("系统繁忙，请稍后重试");
    }
}
```

## 3. 熔断器模式

### 原理

```
┌─────────────────────────────────────────────────────────────────┐
│                      熔断器状态机                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│           ┌──────────────────────────────────┐                   │
│           │           CLOSED (关闭)            │                   │
│           │   正常请求，统计失败率             │                   │
│           └──────────────┬───────────────────┘                   │
│                          │                                       │
│                          │ 失败率超过阈值                          │
│                          ▼                                       │
│           ┌──────────────────────────────────┐                   │
│           │           OPEN (打开)              │                   │
│           │   所有请求直接降级，快速失败        │                   │
│           └──────────────┬───────────────────┘                   │
│                          │                                       │
│                          │ 半开时间后                             │
│                          ▼                                       │
│           ┌──────────────────────────────────┐                   │
│           │        HALF_OPEN (半开)           │                   │
│           │   允许一个请求通过测试             │                   │
│           └──────────────┬───────────────────┘                   │
│                          │                                       │
│            ┌────────────┴────────────┐                          │
│            │                         │                          │
│     请求成功                   请求失败                           │
│            ▼                         ▼                          │
│     ┌─────────────┐           ┌─────────────┐                   │
│     │   CLOSED    │           │    OPEN     │                   │
│     └─────────────┘           └─────────────┘                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### Sentinel熔断

```java
// Sentinel熔断策略
@Service
public class ProductService {

    // 定义资源
    @SentinelResource(value = "getProduct",
                     blockHandler = "getProductBlockHandler")
    public Product getProduct(Long productId) {
        return productClient.getProduct(productId);
    }

    // 熔断降级
    public Product getProductBlockHandler(Long productId, BlockException e) {
        if (e instanceof DegradeException) {
            return getDefaultProduct(productId);
        }
        throw new BusinessException("服务繁忙");
    }
}

// 熔断配置类
@Configuration
public class SentinelConfig {

    @PostConstruct
    public void init() {
        // 慢调用比例熔断
        DegradeRule slowRatioRule = new DegradeRule("getProduct")
            .setGrade(CircuitBreakerStrategy.SLOW_RATIO_RULE)
            .setCount(0.5)                    // 慢调用比例50%
            .setMinRequestAmount(5)            // 最小请求数
            .setStatIntervalMs(10000)          // 统计时长
            .setSlowRatioMaxTime(1000)         // 慢调用阈值1秒
            .setTimeWindow(10);                // 熔断时长10秒

        // 异常比例熔断
        DegradeRule errorRatioRule = new DegradeRule("getProduct")
            .setGrade(CircuitBreakerStrategy.ERROR_RATIO_RULE)
            .setCount(0.5)                    // 异常比例50%
            .setMinRequestAmount(5)
            .setStatIntervalMs(10000)
            .setTimeWindow(10);

        // 异常数熔断
        DegradeRule errorCountRule = new DegradeRule("getProduct")
            .setGrade(CircuitBreakerStrategy.ERROR_COUNT_RULE)
            .setCount(10)                     // 异常数10
            .setMinRequestAmount(5)
            .setStatIntervalMs(60000)         // 1分钟内
            .setTimeWindow(30);              // 熔断30秒

        DegradeRuleManager.loadRules(Arrays.asList(
            slowRatioRule, errorRatioRule, errorCountRule));
    }
}
```

## 4. 限流策略

### 限流算法

```
┌─────────────────────────────────────────────────────────────────┐
│                      限流算法对比                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  计数器算法                                                      │
│  ├─ 简单实现，统计固定时间窗口内的请求数                          │
│  ├─ 缺点：临界问题，可能允许2倍QPS                               │
│  └─ 适用：简单场景                                              │
│                                                                 │
│  滑动窗口算法                                                    │
│  ├─ 细粒化时间窗口，减少临界问题                                  │
│  ├─ Redis ZSET实现                                             │
│  └─ 适用：对精度有要求的场景                                     │
│                                                                 │
│  漏桶算法                                                        │
│  ├─ 以固定速率处理请求，超出桶容量的请求丢弃                      │
│  ├─ 适合流量整形                                                │
│  └─ 适用：保护下游系统                                          │
│                                                                 │
│  令牌桶算法                                                      │
│  ├─ 以固定速率生成令牌，请求需要获取令牌                          │
│  ├─ 允许突发流量                                                │
│  └─ 适用：API Gateway、流量控制                                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 限流实现

```java
// 1. Guava RateLimiter
@Service
public class RateLimitService {

    // 每秒100个令牌
    private RateLimiter rateLimiter = RateLimiter.create(100);

    public String doSomething() {
        // 获取令牌，阻塞等待
        rateLimiter.acquire();
        // 业务逻辑
        return "success";
    }

    public String doSomethingWithTry() {
        // 尝试获取，返回是否成功
        if (rateLimiter.tryAcquire()) {
            return "success";
        } else {
            throw new BusinessException("请求过于频繁，请稍后重试");
        }
    }
}

// 2. Sentinel限流
@Configuration
public class SentinelFlowConfig {

    @PostConstruct
    public void init() {
        // QPS限流
        FlowRule qpsRule = new FlowRule("getProduct")
            .setGrade(RuleConstant.FLOW_GRADE_QPS)
            .setCount(100)                    // 每秒100个请求
            .setControlBehavior(RuleConstant.CONTROL_BEHAVIOR_DEFAULT);

        // 排队等待
        FlowRule queueRule = new FlowRule("createOrder")
            .setGrade(RuleConstant.FLOW_GRADE_QPS)
            .setCount(50)
            .setControlBehavior(RuleConstant.CONTROL_BEHAVIOR_RATE_LIMIT_QUEUEING)
            .setMaxQueueingTimeMs(5000);      // 最多排队5秒

        // 直接拒绝
        FlowRule rejectRule = new FlowRule("delete")
            .setGrade(RuleConstant.FLOW_GRADE_QPS)
            .setCount(10)
            .setControlBehavior(RuleConstant.CONTROL_BEHAVIOR_DEFAULT);

        FlowRuleManager.loadRules(Arrays.asList(qpsRule, queueRule, rejectRule));
    }
}

// 3. 分布式限流（Redis + Lua）
@Component
public class RedisRateLimiter {

    @Autowired
    private StringRedisTemplate redisTemplate;

    private static final String RATE_LIMIT_PREFIX = "rate_limit:";

    public boolean isAllowed(String key, int limit, int window) {
        String redisKey = RATE_LIMIT_PREFIX + key;
        long now = System.currentTimeMillis() / 1000;

        // Lua脚本保证原子性
        String luaScript =
            "redis.call('ZREMRANGEBYSCORE', KEYS[1], 0, ARGV[1]) " +
            "local count = redis.call('ZCARD', KEYS[1]) " +
            "if count < tonumber(ARGV[2]) then " +
            "    redis.call('ZADD', KEYS[1], ARGV[1], ARGV[1]..'-'..redis.call('INCR', 'counter:'..KEYS[1])) " +
            "    redis.call('EXPIRE', KEYS[1], ARGV[3]) " +
            "    return 1 " +
            "else " +
            "    return 0 " +
            "end";

        DefaultRedisScript<Long> script = new DefaultRedisScript<>();
        script.setScriptText(luaScript);
        script.setResultType(Long.class);

        Long result = redisTemplate.execute(script,
            Collections.singletonList(redisKey),
            String.valueOf(now - window),
            String.valueOf(limit),
            String.valueOf(window));

        return result != null && result == 1;
    }
}
```

## 常见面试题

**Q1：什么是雪崩效应？如何防止雪崩？**

> 参考答案：雪崩效应是指当系统中某个服务发生故障时，调用方长时间等待导致资源耗尽，进而引发连锁反应，导致整个系统崩溃。防止雪崩的方法包括：1）设置合理的超时时间；2）使用重试机制配合指数退避；3）实现熔断器模式；4）实施限流策略；5）服务降级返回兜底数据；6）资源隔离（线程池隔离、信号量隔离）。

**Q2：熔断和降级有什么区别？**

> 参考答案：熔断是当失败率达到阈值时，后续请求直接失败，快速返回，避免对下游继续造成压力；降级是在服务不可用时，返回预设的默认值或缓存数据，保证业务能继续进行。熔断是"快速失败"，降级是"有备无患"。通常熔断后会触发降级逻辑。

**Q3：常见的限流算法有哪些？有什么区别？**

> 参考答案：1）计数器算法：简单实现，但有临界问题；2）滑动窗口算法：细分时间窗口，减少临界问题；3）漏桶算法：以固定速率处理请求，适合流量整形；4）令牌桶算法：以固定速率生成令牌，允许突发流量。令牌桶是最常用的算法，Guava的RateLimiter就是令牌桶实现。

**Q4：Sentinel和Hystrix如何选择？**

> 参考答案：Hystrix已经进入维护模式，Sentinel是更活跃的选择。Sentinel相比Hystrix：1）功能更丰富（限流、熔断、降级、系统自适应保护）；2）性能更好（高性能版本）；3）与Spring Cloud Alibaba集成更好；4）配置更灵活。建议新项目使用Sentinel，老项目如果已在用Hystrix可以继续使用或逐步迁移。
