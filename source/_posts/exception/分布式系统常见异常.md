## 前言

分布式系统虽然带来了横向扩展和高可用性，但也引入了传统单体应用不会遇到的复杂问题。网络延迟、节点故障、时钟不同步等问题都可能导致系统行为异常。理解这些常见异常，对于设计健壮的分布式系统至关重要。本文将全面介绍分布式系统中的各类异常及其应对策略。

## 分布式系统经典问题

    @Bean
    public RestTemplate restTemplate() {

        PoolingHttpClientConnectionManager poolingConnectionManager =
            new PoolingHttpClientConnectionManager();
        poolingConnectionManager.setMaxTotal(100);       // 最大连接数
        poolingConnectionManager.setDefaultMaxPerRoute(20); // 每路由最大

        RequestConfig requestConfig = RequestConfig.custom()
            .setConnectionRequestTimeout(2000)  // 从连接池获取连接的超时
            .setConnectTimeout(3000)             // 建立连接超时
            .setSocketTimeout(5000)             // 读取超时
            .build();

        CloseableHttpClient httpClient = HttpClients.custom()
            .setConnectionManager(poolingConnectionManager)
            .setDefaultRequestConfig(requestConfig)
            .build();

        return new RestTemplate(httpClient);
    }
}

## 2. 时钟问题

### 事件顺序

```java
// 时钟偏移导致的问题
public class ClockSkewProblem {

    // 场景：分布式事务中，记录操作时间戳
    // 节点A时间：T1 = 1000（快）
    // 节点B时间：T2 = 990（慢）

    // 事务序列（逻辑上T1先发生，但时间戳T2更小）
    // 1. 节点A：创建订单，时间戳1000
    // 2. 节点B：支付订单，时间戳990（实际后发生，但时间戳更早）

    // 问题：按时间戳排序会出现矛盾

    // 解决方案1：使用逻辑时钟
    // 解决方案2：使用分布式唯一ID（如Snowflake）
}

@Service
public class SnowflakeIdGenerator {

    private final long twepoch = 1288834974657L;
    private final long workerIdBits = 5L;
    private final long datacenterIdBits = 5L;
    private final long maxWorkerId = ~(-1L << workerIdBits);
    private final long maxDatacenterId = ~(-1L << datacenterIdBits);
    private final long sequenceBits = 12L;

    private final long workerIdShift = sequenceBits;
    private final long datacenterIdShift = sequenceBits + workerIdBits;
    private final long timestampLeftShift = sequenceBits + workerIdBits + datacenterIdBits;
    private final long sequenceMask = ~(-1L << sequenceBits);

    private long workerId;
    private long datacenterId;
    private long sequence = 0L;
    private long lastTimestamp = -1L;

    public SnowflakeIdGenerator(long workerId, long datacenterId) {
        if (workerId > maxWorkerId || workerId < 0) {
            throw new IllegalArgumentException("worker Id can't be greater than " + maxWorkerId);
        }
        if (datacenterId > maxDatacenterId || datacenterId < 0) {
            throw new IllegalArgumentException("datacenter Id can't be greater than " + maxDatacenterId);
        }
        this.workerId = workerId;
        this.datacenterId = datacenterId;
    }

    public synchronized long nextId() {
        long timestamp = timeGen();

        if (timestamp < lastTimestamp) {
            throw new RuntimeException("Clock moved backwards");
        }

        if (lastTimestamp == timestamp) {
            sequence = (sequence + 1) & sequenceMask;
            if (sequence == 0) {
                timestamp = tilNextMillis(lastTimestamp);
            }
        } else {
            sequence = 0L;
        }

        lastTimestamp = timestamp;

        return ((timestamp - twepoch) << timestampLeftShift)
            | (datacenterId << datacenterIdShift)
            | (workerId << workerIdShift)
            | sequence;
    }

    private long tilNextMillis(long lastTimestamp) {
        long timestamp = timeGen();
        while (timestamp <= lastTimestamp) {
            timestamp = timeGen();
        }
        return timestamp;
    }

    private long timeGen() {
        return System.currentTimeMillis();
    }
}
```

// 本地消息表实现最终一致性
@Service
public class LocalMessageService {

    @Autowired
    private JdbcTemplate jdbcTemplate;

    @Transactional
    public void createOrderWithMessage(Order order) {
        // 1. 创建订单
        orderMapper.insert(order);

        // 2. 记录消息（在同一事务中）
        String messageId = UUID.randomUUID().toString();
        jdbcTemplate.update(
            "INSERT INTO local_message (id, business_type, business_id, payload, status) VALUES (?, ?, ?, ?, ?)",
            messageId, "ORDER_CREATED", order.getId(),
            JSON.toJSONString(order), "PENDING"
        );

        // 事务提交后，消息状态为PENDING
    }

    @Scheduled(fixedDelay = 1000)
    public void processPendingMessages() {
        // 3. 定时轮询PENDING消息
        List<Message> messages = jdbcTemplate.query(
            "SELECT * FROM local_message WHERE status = 'PENDING' LIMIT 10",
            (rs, rowNum) -> {
                Message m = new Message();
                m.setId(rs.getString("id"));
                m.setBusinessType(rs.getString("business_type"));
                m.setPayload(rs.getString("payload"));
                return m;
            }
        );

        for (Message message : messages) {
            try {
                // 4. 发送消息到MQ
                mqProducer.send(message);

                // 5. 更新消息状态为SENT
                jdbcTemplate.update(
                    "UPDATE local_message SET status = 'SENT' WHERE id = ?",
                    message.getId()
                );
            } catch (Exception e) {
                // 失败，记录重试次数
                jdbcTemplate.update(
                    "UPDATE local_message SET retry_count = retry_count + 1 WHERE id = ?",
                    message.getId()
                );
            }
        }
    }
}

### 幂等处理

```java
// 幂等键实现幂等
@Service
public class IdempotentService {

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    public Result processRequest(Request request) {
        String idempotentKey = request.getIdempotentKey();

        // 1. 检查是否已处理
        String cached = redisTemplate.opsForValue().get("idempotent:" + idempotentKey);
        if (cached != null) {
            return JSON.parseObject(cached, Result.class);
        }

        // 2. 标记处理中（防止并发重复处理）
        Boolean success = redisTemplate.opsForValue().setIfAbsent(
            "idempotent:" + idempotentKey + ":lock",
            "LOCK",
            Duration.ofSeconds(30)
        );

        if (!success) {
            throw new BusinessException("请求正在处理中，请稍后");
        }

        try {
            // 3. 执行业务逻辑
            Result result = doProcess(request);

            // 4. 存储结果
            redisTemplate.opsForValue().set(
                "idempotent:" + idempotentKey,
                JSON.toJSONString(result),
                Duration.ofHours(24)
            );

            return result;
        } finally {
            // 5. 释放锁
            redisTemplate.delete("idempotent:" + idempotentKey + ":lock");
        }
    }
}
```

## 常见面试题

**Q1：CAP定理是什么？分布式系统如何选择？**

> 参考答案：CAP定理指出分布式系统无法同时满足一致性（Consistency）、可用性（Availability）和分区容错（Partition Tolerance）。由于网络分区在分布式系统中不可避免，实际设计时必须在C和A之间权衡。CP系统（如Zookeeper、HBase）优先保证一致性；AP系统（如Cassandra、Eureka）优先保证可用性。大多数互联网系统选择AP，通过最终一致性保证业务可用。

**Q2：什么是分布式事务？有哪些实现方案？**

> 参考答案：分布式事务是指事务的参与者分布在不同的节点上，需要保证事务的ACID特性。实现方案包括：1）两阶段提交（2PC）：强一致但性能差，存在协调者单点问题；2）三阶段提交（3PC）：引入超时机制，改善了协调者单点；3）TCC（Try-Confirm-Cancel）：业务层面的补偿模式，性能好但侵入性强；4）本地消息表+MQ：最终一致性，适合异步场景；5）Seata等分布式事务框架。

**Q3：如何处理分布式系统中的时钟问题？**

> 参考答案：1）避免依赖绝对时间戳，使用逻辑时钟（如Lamport Timestamp）；2）使用分布式唯一ID（如Snowflake）代替时间戳排序；3）使用向量时钟记录因果关系；4）在数据库主从场景，使用半同步复制或强制读主库；5）对于延迟敏感的场景，使用Ping对时钟进行校准。

**Q4：如何防止分布式系统雪崩？**

> 参考答案：1）超时设置：合理设置调用超时，避免无限等待；2）熔断器：当失败率超过阈值时快速失败；3）限流：限制并发请求量；4）降级：返回兜底数据，保证服务可用；5）隔离：使用线程池隔离不同服务；6）资源保护：合理配置连接池、线程池；7）监控告警：及时发现问题。
